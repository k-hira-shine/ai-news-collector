## 🔴 CRITICAL

### 1. Buzzランキングが約2週間、実質凍結している

- **現況**: 公開 `buzz.html` は 15アカウント中12が `snap_date=2026/06/19 03:13 JST` で凍結。更新継続は `fiction_log`/`AiFreak_tool`(07/01)・`taziku_co`(06/22) のみ。
- **原因**: 2026-06-21 の `xquik/x-tweet-scraper` 新ビルドで maxItems が「全searchTerms合算の上限」に変化（X収集で対応済みの事故と同型）。`collector.py` は 1 run=1アカウントに修正済みだが、`run_buzz.py:76-127`（`fetch_accounts_batch`）は今も**全15アカウントを1 run・maxItems=100 でバッチ**。先頭1〜2アカウントが100枠を食い潰し残り13が飢餓。
- **証拠**: `data/buzz_collection_metrics.jsonl` が 6/19まで `accounts:15 / fetched_items:~1267` → 6/22以降ずっと `accounts:1〜2 / fetched_items:100`。
- **なぜ無検知**: データ不変→ランキング不変→`ranking_top20_overlap=100%`→`guardrail_status=pass`。overlap単独判定にした結果、停滞（更新ゼロ）を「安定」と誤認。daily_check も「Buzz合格 overlap=100%」と表示。
- **同型欠陥（未修正）**: `account_collector.py`（money/sns共有 maxItems=200合算）、`money_collector.py`/`sns_collector.py`（クエリ3本/バッチで maxItems共有）。
- **推奨**: collector.py と同じく run_buzz を 1 run=1アカウント化（従量課金でコスト不変）＋「per-account取得0件がN回連続」を guardrail に追加。

### 2. 致命的失敗が run_status に反映されず公開もされない（`if: always()` 欠落）

- `.github/workflows/collect.yml` の `Commit & push data` / `Deploy` ステップに `if: always()` が無い（3 workflow とも0件）。
- `main.py:32-45` は例外時に run_status.json へ error を書いて re-raise するが、ステップ失敗により後続 push がスキップ→**エラー状態も収集済み daily JSONL も分析JSONも Actions ワークスペースごと消滅**（Apify課金だけ発生）。
- 収集成功後の後段ステップ（build_tools / gemini_collector / build_buzz 等 約10ステップ）が1つ落ちても当日データ全損。
- サイト右下の赤バナーはこの修正なしには機能しない。
- **推奨**: push・直前の cost tracking / sync_nav に `if: always()`（または収集直後に中間 commit/push）。

### 3. HTML生成失敗の握りつぶし

- `main.py` の dashboard(index.html) 生成（207行付近）/ strategy.html 生成（217行付近）/ tools 生成が `try/except Exception: logger.error(...)` のみ。anomalies に積まず・再送出せず・write_run_status も呼ばない。
- 空ページ化・strategy更新停止が起きてもどの監視にも掛からない（対照的に run_money は `sys.exit(1)` で伝播）。
- **推奨**: 2つの except を anomalies 追加（severity=critical）か raise に変更。

### 4. SNSダッシュボードのストアドXSS

- `sns_dashboard.py:509` が収集X投稿本文（攻撃者制御・最大800字）を `json.dumps(..., ensure_ascii=False)` して `sns_dashboard.py:285` の `<script>` ブロックに生挿入。`json.dumps` は `</script>` をエスケープしない（実証済み）。
- `</script><script>…</script>` を含むポストが収集・掲載されると公開ページで任意JS実行。
- 加えて `_render_post_card`（563-573行）で `summary`/`mind_theme`/`key_insights`/`author_display` がエスケープなし挿入（`content` のみ `<` 置換）。
- **推奨**: `<script>` 埋め込み前に `</`→`<\/` 置換。sns/money の全ユーザー由来・LLM由来フィールドに `html.escape()` 適用（他ビルダーは適用済み）。

### 5. XSS→localStorage の GitHub PAT 窃取に連鎖

- `docs/reviews.html:354` が repoスコープの GitHub PAT を `localStorage['gh_pat']` に平文保存（`docs/tools.html` も同キー）。
- `docs/` 配下は GitHub Pages 上で同一オリジン→localStorage 共有。上記XSSが `localStorage.getItem('gh_pat')` を読み外部送信可能＝リポジトリ改ざん権限の奪取。
- **推奨**: (1) XSSを塞ぐ (2) PATをlocalStorage永続保存しない（sessionStorage/Worker中継） (3) fine-grained・最小権限・短期限。
- **是正済み**: buzz.html は Worker中継化で PAT がブラウザに出ない。git remote にトークン埋め込み無し。

### 12. requirements.txt がほぼ上限未固定
